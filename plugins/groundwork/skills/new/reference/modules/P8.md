# P8 Heavy operations kit

## When on
Profile check P8 is "yes": a large project that spans several sessions and several weeks. Signals: several weeks or more, several sessions · several people, staged releases. Small CLIs · scripts · libraries are usually "no", and with it off no ledger · handoff · status board · lock script · side-branch scripts (`trunk.sh` and its runbook) get made.

## Questions (one message)
Show them at once as a numbered list and end by asking "as recommended, or just the numbers to change". Ask only the changed numbers, separately, to the end.

1. **Keeping a ledger** — recommended: yes. Record defects · UX · requests · security · debt by number in one place. Rows hold only the current state and an evidence pointer (history is git), and finished rows move to `docs/archive/` per bundle. The current situation lives in the handoff, not the ledger. Reason: when sessions change, knowing what is open comes down to memory. Appending fix history to rows grows the ledger into a history log (measured example: 978KB, 15KB in one row), and a hand-updated 'current' block froze and stayed on as a source of truth.
2. **Handoff doc** — recommended: yes. Write only what comes next, 10KB or less (the format is `templates/docs/handoff.md`), and move facts that stay the same across sessions to the status board. End at a work boundary (or on a context hook notice) and confirm with the carry-over check that nothing was dropped. Reason: a long session rereads the whole context every turn (measured example: main average 420,000 tokens, 56,000 at the start of a new session), and carrying finished work · fixed facts along bloated the handoff to 30KB.
3. **Heavy-command lock** — recommended: yes when several agents run locally (otherwise no). Wrap build · typecheck · test · e2e in one lock and a wait for free memory. Also set a cap on concurrent agents (the value comes from the work environment's memory and existing rules, e.g. 6). Reason: running at the same time, they kill each other through out-of-memory.
4. **Push bundles and CI minute budget** — recommended: push once per bundle, set a monthly CI minute budget, and use path filters · duplicate-run cancellation. Run the heavy full e2e (several browsers · tens of minutes) by hand before a release rather than on every push; the push gate holds only typecheck · lint · build · fast tests. Do not set the CI spending limit to $0. Reason: once the budget runs out, jobs are blocked and deploys stop.

## ADR
None. Instead of ADRs this module makes `docs/ledger.md` · `docs/plans/handoff.md` · `docs/plans/status.md` · `scripts/heavy.sh` · `scripts/trunk.sh` · `docs/runbooks/trunk.md`. Until stage 4 the answers stay in the spec section 'Hard rules · operating answers'.

## CLAUDE.md rule lines
- Defects · UX · requests · security · debt are numbered in `docs/ledger.md` (row = current state + evidence pointer, 300 characters or less, finished rows move to `docs/archive/` per bundle). Closing a plan also sets that plan's rows to `done`. Get the open rows with `rg '^\| [A-Z]+-[0-9]+ .*\| (open|active|verifying|on hold)[^|]*\|$' docs/ledger.md` and do not copy them into the handoff. End a session at a work boundary and overwrite `docs/plans/handoff.md`, keeping its format (10KB or less, carry-over check passed).
- Run heavy commands (build · typecheck · test · e2e) with `scripts/heavy.sh <GB> <command>`. Concurrent agents never exceed the cap (answer 3), and push once per bundle.
- Side branch: open sessions at the root and move around with `cd`. A side worktree (made by `bash scripts/trunk.sh open <name>`) counts as both the preference and the consent, so do not make one yourself and do not use EnterWorktree. Instead of the finishing menu and 'ask before merging': review mark → `bash scripts/trunk.sh merge <name>`. Do not wrap `trunk.sh` in heavy.sh. Read `docs/runbooks/trunk.md` before opening a side branch and before calling an execution skill. This line and the runbook come before skill instructions.
- Before starting work, read the status board and `bash scripts/trunk.sh` (milestones · open side branches · missing commits · things to tidy).

Where the side-branch line and the session-start line go: in a single repo, `{{module_rules}}`; in an umbrella, the umbrella `CLAUDE.md` 'Shared conventions' (not in the umbrella's repo `CLAUDE.md` files). The rule body is not stretched into the lines; it lives in the runbook (`docs/runbooks/trunk.md`).

## Scaffold
- `docs/ledger.md` (`templates/docs/ledger.md`): the numbering scheme for defects · UX · requests · security · debt, row rules, archive rules. No current-state block and no 'next number' line (the handoff holds the current state; numbers come from `rg`).
- When making the ledger, attach a row-length check to the one-line gate: `bash scripts/rg-none.sh -n '^\| (DEF|UX|REQ|SEC|DEBT)-[0-9]+ .{300}' docs/ledger.md` (copy `templates/gates/rg-none.sh` to `scripts/`). Checking rg locally and uncommenting the ripgrep step of `ci.yml` follow the `ci.yml` notes in `reference/baseline-scaffold.md`. An umbrella does not attach it to the repo gates, since the docs hook already checks it.
- `docs/plans/handoff.md` (`templates/docs/handoff.md`): its format — Now · Next · Scheduled · For you · Open items · Closed this session.
- `docs/plans/status.md` (`templates/docs/status.md`): the status board — the `## Milestones` table (first milestone `v0.1.0`, status `open`) and `## Facts` (source · check date on each line). The first milestone is the first fact, so it is made in stage 5 together with the ledger · handoff.
- Copy `scripts/trunk.sh` (`templates/gates/trunk.sh`) and `scripts/lib/trunk/` (`templates/gates/lib/trunk/`) together. An umbrella puts them in the umbrella `scripts/`. Also add the runbook `docs/runbooks/trunk.md` (`templates/docs/runbook-trunk.md`). The rule bodies for side branches · merging · the map · milestones are there.
- `verify` per repo: one command that is the one-line gate (`check`) plus build and e2e, as far as they apply. A pnpm repo has it as the `verify` script of `package.json`; other repos as the `install` and `verify` targets of a Makefile. It must run as is in a fresh worktree after install and change no tracked files (lockfile · generated output · formatting), and e2e takes `CI=1` and `E2E_PORT` (`reference/client-forms.md` section C).
- `scripts/heavy.sh` (`templates/gates/heavy.sh`): lock + wait for free memory. If item 3 is "no", this file is not made.
- In CLAUDE.md, the concurrent-agents and push-bundle line, the side-branch line, the session-start line. In stage 5, before the first task, make whichever of the ledger · handoff · status board is missing.

Filling the ledger · handoff · status board (stage 5, before the first task). Values come only from the plan. Do not read code to find or fix defects, and touch nothing but this scaffold before the user picks a task:

| Placeholder | Value |
|---|---|
| `{{project_name}}` | The project name (the same as `{{project}}` in CLAUDE.md) |
| `{{first_milestone}}` | A one-line name · goal for the status board's `v0.1.0` milestone. It starts as the name of the first spec's scope, and the user can change it |

| `{{next_goal}}` | One line for the next piece of work in the plan |

### Turning it on later
In a project with P8 off, when the time set by the P8-off line of `CLAUDE.md` comes:

1. Ask the four `## Questions (one message)` above in one message, exactly as the first time. If the answer is not to turn it on, continue the work at hand.
2. If it is turned on, change the P8 cell of the `CONTEXT.md` profile table to `yes`, and add P8 to the modules that are on in the `CLAUDE.md` head. Put the rule lines where stage 4 puts them (`reference/baseline.md` section D) (without the `heavy.sh` line if answer 3 is "no").
   - Single repo: replace the P8-off line of `CLAUDE.md` with this file's four rule lines (ledger · `heavy.sh` · side branch · session start).
   - Umbrella: replace the P8-off line of the umbrella `CLAUDE.md` with the side-branch line · session-start line, and put the ledger line · `heavy.sh` line in each repo `CLAUDE.md` at the rule-line slot (before the spec-sections line). Not in the umbrella `CLAUDE.md` (7.9KB cap).
   - In each repo `CLAUDE.md`, replace the sentences after `Commits go straight to main.` (the off value 'Branch only when asked…') with the P8-on value of `reference/baseline.md` `{{commit_rule}}` (the umbrella's repos write that value's parenthesis as "(the side-branch line in the umbrella `CLAUDE.md`)").
3. Per the answers, make the ledger · handoff · status board (milestone `v0.1.0`) · row-length check (copy `rg-none.sh`, add it to the one-line gate, the ripgrep step of `ci.yml`) as in the scaffold above, in one commit `docs: turn on the ledger and handoff`.
4. If answer 3 is "yes", put `scripts/heavy.sh` and the gate change in a separate commit `chore: add the heavy-command lock`.
5. Make `scripts/trunk.sh` · `scripts/lib/trunk/` · the runbook · `verify` per repo as in the scaffold above, in a separate commit `chore: add the side-branch scripts`. Add the `verify` line (the `{{cmd_verify}}` line of `templates/CLAUDE.md.tmpl`) to the commands section of each repo `CLAUDE.md`. Add `.worktrees/` to `.gitignore` if it is missing, exclude `.worktrees/` from the tool configs (tsc · vitest · biome · eslint · knip), and in a single repo (the umbrella's repos included) put the `claudeMdExcludes` of `templates/claude-settings.json` into `.claude/settings.json` (if the file exists, add only the key; not at the umbrella root). A plan that is `active` at the moment P8 is turned on finishes on main; side branches start from the next plan.
6. Answer 4 makes no file. The answer stays in the `CLAUDE.md` rule lines.
