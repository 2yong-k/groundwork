# P4 AI pipeline

## When on
Profile check P4 is "yes": AI · LLM output drives product behavior. Signal words: AI · LLM, prompts, agents.

## Questions (one message)
Show them at once as a numbered list and end by asking "as recommended, or just the numbers to change". Ask only the changed numbers, separately, to the end.

1. **Output validation** — recommended: treat model output as untrusted input and validate its schema and value ranges before using it. On a validation failure, discard or retry. The output of a model that read external content (web · documents · user posts) cannot call money · permission · outbound-send actions directly; it goes through server validation or human approval. Reason: models produce plausible but wrong values. When external content decides a verdict or money, prompt injection is the attack path.
2. **When confidence is low** — recommended: below the confidence threshold, or when the models do not agree, do not proceed automatically; send it to human review. Reason: being silently applied when wrong costs more.
3. **Caps and cost records** — recommended: cap call count · time · cost and stop when a cap is exceeded, and leave a one-line usage log per call. Reason: with only per-round caps the whole job can run forever, and without records the cost shows up late.
4. **Data lifetime** — recommended: load idempotently by stable id and set a retention period. Reason: feeding the same input again piles up duplicates, and old data loses any basis for deletion.

## CLAUDE.md rule lines
- Model output is used only after it passes schema · range validation. Output that read external content cannot call money · permissions · outbound sends directly; it goes through server validation or human approval. Low confidence goes to human review and never proceeds automatically.
- Every model call has count · time · cost caps, and each call leaves one usage log line.

## Scaffold
- Output schema validation test: malformed output · out-of-range values · empty output are all rejected and go to the human review path.
- The one-line usage log format (e.g. call id · model · input/output tokens · cost · duration · result) and one wrapper that writes it.
- One point that stops when a cap is exceeded. Do not rebuild what the baseline (CI · config validation) already does.
