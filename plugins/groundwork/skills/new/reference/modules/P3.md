# P3 Public surface

## When on
Profile check P3 is "yes": there are APIs · uploads · websockets · proxies reachable without login. Signal words: public API, uploads · websockets, receiving webhooks · proxy.

## Questions (one message)
Show them at once as a numbered list and end by asking "as recommended, or just the numbers to change". Ask only the changed numbers, separately, to the end. It goes right after the stage 2 'Auth' question.

1. **Anonymous threat question** — recommended: write down, per path, what an anonymous user can call and how much (the public path table). Reason: without a list, even framework features and internal services you do not use stay open.
2. **Request count · body size limits** — recommended: set them as a global default and relax them per path (deny by default). Reason: if each path sets its own, a new path opens with no limit.
3. **Where ownership is checked** — recommended: check at the server boundary, verify signer = authenticated principal, and take input through an allowlist. Reason: leave it to the UI and a direct call goes around it.
4. **DB access default** — recommended: row-level deny by default (a new table turns it on in the migration that creates it). Reason: turn it on later and you have to hunt down the already open tables one by one.
- (only with a webview shell app, added as number 5) **Bridge security** — recommended: a bridge allowlist, loading only your own origin, file access off, external links to the system browser. Reason: if an external page shows in the webview, the bridge exposes device features to it. The answer goes into `{{bridge_policy}}`.

## CLAUDE.md rule lines
- A new public path first updates the ADR's public path table. Request count · body size limits are global defaults; a path only relaxes them.
- Never trust owner · permission values the client sent; tie them to the authenticated identity. A new table turns on row-level security in the migration that creates it.

## Scaffold
- Global limit middleware (request count · body size; one caller-identification function also sets the rate-limit key; IPv6 is grouped by /64) — the builder writes it for the stack.
- 1 HTTP check test per endpoint kind: no auth · someone else's resource · oversized body · repeated calls are all rejected.
- (When receiving webhooks) one verification function and a test per receiving path: verify the signature over the raw body before parsing (between our own services, an HMAC of `"<ts>.<raw body>"`), reject outside the time window · on a signature mismatch, compare in constant time. Each receiver uses a different secret, and startup fails if two share the same secret. A wrong secret silently rejects every webhook, so when rejections pass a threshold, call the B11 alert function.
- Do not rebuild what the baseline (secret scanning · CI) already does.
