# P5 i18n and URLs

## When on
Profile check P5 is "yes": two or more languages, or search visibility matters. Signal words: two or more languages, overseas users, search visibility · SEO.

## Questions (one message)
Show them at once as a numbered list and end by asking "as recommended, or just the numbers to change". Ask only the changed numbers, separately, to the end. For a native app only, ask item 1 as "language resource files + deep link rules" instead.

1. **URL strategy** — recommended: a path prefix `/[lang]`, the default language also allowed without a prefix, hreflang · sitemap provided. Reason: if only a cookie · header sets the language, search engines cannot see the per-language pages.
2. **Supported languages** — recommended: pick only the languages needed now and write down the steps for adding one. Reason: every added language brings missing keys and font problems.
3. **User content language** — recommended: store the language of content users (or AI) wrote as data (a language column set at writing time). Reason: screen language and content language differ.
4. **Time** — recommended: store in UTC and show in the viewer's locale · time zone. Deadlines are written with their time zone. Reason: stored in the server's local time, a deadline looks different to each user.

## CLAUDE.md rule lines
- Screen text is written only as keys of the per-language dictionaries (no hard-coding). The dictionary type fails typecheck when a key is missing.
- Store and transmit time as UTC instants and convert it to the viewer's locale only for display. Store user content language as data.

## Scaffold
- The per-language dictionary type (every other language must fill the base language's key set; a missing key fails typecheck).
- Hard-coded screen text check: with Biome, turn on `style/noJsxLiterals` in `biome.json` with `"level": "error"` (Biome 2.2.4 or later. It is not in the recommended set, and turning it on with just `"on"` leaves the default severity at info, so the gate does not fail). It also catches JSX text folded over several lines, and generic calls · comparisons are not flagged. Allowed: a `biome-ignore lint/style/noJsxLiterals: <reason>` comment right before it (inside JSX, `{/* … */}`) or `allowedStrings` (strings identical down to whitespace). Lint is already in `{{cmd_check}}`. With another linter, the same rule (ESLint `react/jsx-no-literals`).
- CJK font rules in the design tokens (per-language font stacks and line heights). Tokens live in `design/tokens.json`, and the baseline's contrast check is used as it is.
