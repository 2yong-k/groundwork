# P1 Numbers and units

## When on
Profile check P1 is "yes": quantities that must never be wrong change hands, such as money, assets or points. Signal words: payments, balance · points, settlement · fees.

## Questions (one message)
Show them at once as a numbered list and end by asking "as recommended, or just the numbers to change". Ask only the changed numbers, separately, to the end.

1. **Amount representation** — recommended: store and compute in integer minor units, transmit as a string or bigint, no float. Reason: if each layer uses a decimal type, precision drifts in the conversions.
2. **Rounding** — recommended: one function per direction in the boundary module, and everything uses only those. The default direction never works against the user. Reason: if the caller decides, the same value differs from screen to screen.
3. **Ratio scale** — recommended: store and transmit ratios · probabilities · prices as a single 0..1 fraction and convert only on screen. Write exceptions down with their field names. Reason: if 0..100 slips in even in one place, it is silently 100 times wrong.
4. **Outcome of actions that move money** — recommended: three states — not sent / sent · unconfirmed / confirmed; after sending, lock resending and tie retries to an idempotency key. Reason: an action whose response is late or cut off looks like a "failure" and invites a duplicate send.
- (only with a native app, added as number 5) **In-app payments** — recommended: payments for digital goods follow the store's in-app purchase rules, written down separately from payments for physical goods · services. Reason: a rejection in review means redesigning the payment flow. The answer goes into `{{iap_policy}}` of ADR `mobile-release`.

## CLAUDE.md rule lines
- Amounts are integer minor units, transmitted as string/bigint, no float. Rounding uses only the per-direction functions of the boundary module. Ratios use a single 0..1 scale, converted only on screen.
- Handle actions that move money in three states — not sent / sent · unconfirmed / confirmed — and tie retries after sending to an idempotency key.

## Scaffold
- The amount boundary module (representation conversion and per-direction rounding functions) — the builder writes it for the stack.
- 1 property test with an independent oracle: on random inputs the module's result equals the value another method gives (e.g. arbitrary-precision arithmetic), and rounding sums never work against the user.
- A "sent · unconfirmed" state type (an enum of the three states). Do not rebuild what the baseline (CI · lint) already does.
